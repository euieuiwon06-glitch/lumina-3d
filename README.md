# LUMINA 3D — 블렌더 모델로 만든 360° 게임 데모

블렌더로 제작한 배경 8종과 루미 캐릭터 6종을 그대로 변환해, **걸어 다니며 시점을 360° 돌려 볼 수 있는 3D 공간**에서 첫 항해까지의 이야기를 플레이하는 단일 플레이어 웹 데모다. 온라인 멀티플레이가 아니며 주민은 코드로 움직이는 NPC다.

- 기준 문서: `../LUMINA_게임기획안_v2.md`, `../01_확정_디자인가이드.md`, `../02_이미지유지_구현명세.md`, `../03_CLAUDE_CODE_작업지시.md`
- 진행 기록·구조: `IMPLEMENTATION_PLAN.md` · 에셋 한계: `ASSET_GAPS.md`
- 기존 2.5D 데모(`../lumina`)는 수정하지 않았다.

## 실행

```bash
npm install
npm run dev            # http://localhost:5190
npm test               # 퀘스트 전이·보상 중복·저장 복구·장면 이동·항해 목적지·퍼즐·보행 격자·A* (14개)
npm run build          # dist/ (상대 경로)
node tools/playtest.mjs [--w 1280 --h 720]   # dev 서버 실행 중 전체 흐름 자동 플레이
```

주소 옵션: `?reset` 저장 초기화 · `?skipIntro` · `?scene=ice` 등 장면 바로 열기(검수용) · `?debug` 보행 격자·동선 표시 · `?lowres` 저해상도 · `?tm=neutral` 톤매핑 비교
콘솔: `lumina.state`, `lumina.spots()`, `lumina.approach('npc','pogeun')`, `lumina.goto('overlook')`, `lumina.reset()`

## 조작

| 입력 | 동작 |
|---|---|
| WASD·방향키 (Shift 달리기) | 카메라 기준으로 걷기 |
| 바닥 클릭 | 그 지점까지 경로를 찾아 걷기. 주민·설치 지점·출구·결정을 누르면 걸어가서 바로 상호작용 |
| 마우스/터치 드래그 | 시점 360° 회전·상하 기울기 |
| 휠 | 확대·축소 |
| Q / R, 오른쪽 아래 버튼 | 시점 45° 돌리기, 캐릭터 뒤로 맞추기 |
| E | 가까운 대상과 상호작용 · Esc 패널 닫기 |
| 아래 도크 / 왼쪽 팔레트 | 빛의 형태 / 색 (어디서나) |
| 빛 제작실 작업대 | 움직임·밝기 (작업대 위에 빚은 빛이 미리 보임) |

## 플레이 흐름(약 10~15분)

빛 제작실 → 캡슐 마을 → 촉수 산책로 → 항해 전망대 → (출항) 얼음 성운 / 태양 정원 / 황혼 합류지 → 귀환

1. **조용한 쉼터**(구름 루미 포근, 캡슐 마을): 수락 → 씨앗 1. 작업대에서 맥동·밝기 60 이하 → 쉼터에 놓기. 틀리면 거두기로 씨앗 복귀.
2. **살구빛 산책로**(꽃 루미 살구, 촉수 산책로): 가운데 봉오리에 따뜻한 빛 → 노을빛 배색. 촉수 아래 숨은 씨앗도 찾을 수 있다.
3. **첫 항로**(결정 루미 보라, 항해 전망대): 빛 오르간에 빛을 보내면 오른쪽 위 게이지가 목적지를 가리킨다. 차가움=얼음 성운, 따뜻함=태양 정원, 중간=황혼 합류지. 첫 항로는 얼음 성운 도착으로 완료.
4. **결정의 노래**(덩굴 루미 리본, 얼음 성운): 결정 3개가 빛+소리로 4음 → 패널 버튼이나 결정을 직접 눌러 따라 하기. 틀리면 몇 번째인지 표시, 다시 듣기·다시 하기.
5. **산책로의 마지막 빛**(포근): 천천히 맥동하는 빛을 산책로 끝에 → 잠든 봉오리들이 함께 깨어나고 마무리 장면.

## 블렌더 → 게임 변환

```bash
node tools/export-all.mjs                         # 8개 장면 전부(GLB·파노라마·격자, RTX 기준 약 15분)
node tools/export-all.mjs ice --no-pano           # 일부만, 파노라마 생략
node tools/export-all.mjs --no-grid --no-pano     # 재질만 고쳤을 때 GLB만
node tools/export-all.mjs --characters            # 캐릭터 6종
node tools/gridcheck.mjs; node tools/gridview.mjs walkway   # 보행 격자 연결 검사·평면도
```

원본 `.blend`는 열어서 메모리에서만 변환하고 저장하지 않는다. 장면마다:

| 산출물 | 내용 |
|---|---|
| `scenes/<id>.glb` | 근경(보이는 컬렉션). 절차적 재질은 대표 색·거칠기·발광으로 환산, 커브→메시, 오브젝트당 3.6만 삼각형 이하, Draco |
| `scenes/<id>_pano.jpg` | 원경 컬렉션(우주·구름바다·먼 섬·산맥)과 월드 하늘을 Cycles 등장방형 4096×2048로 렌더. 하늘 구체와 환경광에 사용 |
| `scenes/<id>.json` | `NAV_동선표시`(ENTRY/EXIT/POI/QUEST), 조명, 기준 카메라, 보행 격자(0.25m, 최대 3층, cm Int16) |

보행 격자: `ENV_*_Walkable` 컬렉션의 위를 향한 면 → 장애물(다른 컬렉션)과 반경 0.26m 이내·머리 위 1.2m 이내에 걸리면 제외 → 칸 사이 높이 차 0.22m 이하로 이어진 영역 중 큰 영역만 남김.

## 알려진 한계

- 재질은 노이즈·램프·면 방향 노드를 **대표 색 하나로 환산**해 원본 렌더의 얼룩·가장자리 빛·표면 무늬가 줄었다(얼음의 면 무늬, 막의 프레넬 등). 조명·색은 AgX + 채도 보정으로 맞췄지만 원본 EEVEE 렌더와 같지는 않다.
- 캐릭터는 리그가 없어 팔·다리 파츠를 회전시키는 단순한 걷기·손 흔들기만 있다.
- 파노라마는 장면 시작점에서 구운 원경이라, 멀리 걸어가면 원경과의 시차가 약간 어긋날 수 있다.
- 일부 동선 표시가 원본에서 섬 밖에 떠 있어(예: 캡슐 마을 입구 문턱) 가장 가까운 걸을 수 있는 칸으로 옮겨 쓴다.
- 잠긴 출구(전망대 반대편 길, 얼음 성운 징검다리 등)는 이유만 보여주고 열리지 않는다.
- 교환·공명·촉수 장식·항해 기록·멀티플레이는 이번 범위에서 제외(가짜 버튼 없음).
